# Layout probe split qualification refresh

Issue: #210, stage 3 (ADR-0020). Status: **corpus, viewers and cross-target
measurement refreshed**; release evidence is `pending_ci` until a clean-commit
target aggregate is recorded.

## Change

The qualification corpus picks each source's `layout-closure-heavy` cell from
`font_subset::layout_glyph_ids`. That set used to be whatever the retired
traversal validator marked: every `GlyphId16` field it visited in GSUB, GPOS
and GDEF, including ClassDef and GDEF tables. Coverage and ClassDef format 2
ranges only contributed their first and last glyph. ADR-0020 replaces that
accidental definition. A glyph is now layout-referenced when a Coverage table
of a GSUB or GPOS lookup subtable includes it, counting whole ranges and
extension subtables. GDEF and class definitions are excluded.

## Corpus diff

214 cells change, all `layout-closure-heavy`. The issue predicted about 4,
from a scratch measurement that expanded Coverage ranges but kept GDEF. The
maintainer reviewed this larger diff and accepted it before regeneration.

| Sources | Cells | Change | Why |
| --- | ---: | --- | --- |
| Xiaolai chunks | 203 | success → not applicable | No GSUB/GPOS lookup coverage in these chunks includes a mapped glyph. The old walker's marks came from GDEF, ClassDef or other glyph fields (substitutes, components) |
| Lilita (`i7dPIFZ9Zz…`) | 1 | success → not applicable | Same cause: its old probe, U+2020, is in no lookup coverage |
| Xiaolai chunks | 4 | different scalars | The carrier set shrinks to coverage-referenced glyphs |
| Excalifont ×2, Nunito ×3, Noto Emoji | 6 | different scalar | The reachable glyph set changes, so the first probe that exercises layout is a different mapped glyph |

No other class moves, and every other cell's bytes, identity and notice are
unchanged.

New totals: **780 successful cells, 1007 traced cells, 662 distinct viewer
executions** (655 official-chunk, 7 Noto Emoji). Previously 984 / 1211 / 864.

A variant that kept GDEF ClassDef glyphs was also measured. It shrinks the
diff, but it selects a Xiaolai probe (`[U+B194, U+11BC]`) whose subset fails a
later `Validate` check. The layout walker accepts that subset; the failure is
elsewhere in validation and predates this work.
