## Exact-pinning choices

- A crates.io profile can use exact requirements `=0.47.0` for both public crates, commit `Cargo.lock`, and run Cargo with `--locked` or `--frozen`. A bare `"0.47.0"` is a compatible range, not an exact requirement; Cargo documents `= 1.2.3` as exact and `--locked` as rejecting dependency-resolution drift. [Source: Cargo version requirements](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#version-requirement-syntax), [Cargo `--locked`](https://doc.rust-lang.org/cargo/commands/cargo-build.html#manifest-options)
- A Git profile can pin both workspace crates with `git = "https://github.com/linebender/resvg"` and `rev = "3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707"`; use the peeled commit, not a movable branch and not only the annotated tag name. Cargo documents `rev` commit selection and also records the commit in `Cargo.lock`. [Source: Cargo Git dependencies](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#choice-of-commit)
- Upstream also publishes `resvg-0.47.0.tar.xz` as a source archive with vendored Rust dependencies; GitHub records SHA-256 `22d12bf638479688f3762ac951446f51ca75cb24c6853b23384f96fda02096c5`. This is an archive-level pinning option. [Source: upstream v0.47.0 release](https://github.com/linebender/resvg/releases/tag/v0.47.0)
- The visual profile must also pin enabled features and the full lockfile. `resvg` defaults enable `text`, `system-fonts`, `memmap-fonts`, and `raster-images`. For a self-contained gate, the relevant library feature set is `default-features = false` with `text` and, when corpus SVGs contain raster images, `raster-images`; omit `system-fonts` and `memmap-fonts`. The upstream `resvg` executable itself requires `text`, `system-fonts`, and `memmap-fonts`, so the deterministic profile needs its own library caller rather than the stock binary. [Source: resvg features and binary requirements](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/Cargo.toml#L13-L44), [usvg features](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/Cargo.toml#L16-L59)

## Raster dimensions, transforms, and defaults

- `Tree::size()` is the resolved SVG `width` and `height`. During parsing, usvg flattens the root `viewBox`/`preserveAspectRatio` mapping into a root-group transform. `resvg::render` then applies the caller-supplied transform as an additional root transform; it performs no automatic fit. [Source: tree size](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/tree/mod.rs#L1581-L1605), [viewBox flattening](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/converter.rs#L350-L357), [root transform](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/converter.rs#L418-L435), [render API](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/lib.rs#L28-L50)
- Upstream's native-size example allocates `tree.size().to_int_size()` and renders with the identity transform. `Size::to_int_size()` rounds each floating dimension to nearest integer and clamps it to at least one; it does not use `ceil`. This sizing rule must be part of the viewer profile. [Source: resvg minimal example](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/examples/minimal.rs#L25-L28), [tiny-skia sizing](https://github.com/linebender/tiny-skia/blob/e48b9027762d33731e60e40eb17eaa4f583b0185/path/src/size.rs#L186-L193)
- The CLI's `--width`, `--height`, and `--zoom` modes first derive an integer target size and then apply a scale transform computed from the integer source and target sizes. Using any of them changes both dimensions and sampling; native identity rendering avoids that extra degree of freedom. [Source: fit sizing and transform](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/main.rs#L387-L423), [normal render path](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/main.rs#L727-L749)
- A new tiny-skia pixmap is transparent black. resvg documents rendered content as sRGB; the CLI only makes the canvas opaque when `--background` is supplied. [Source: pixmap initialization](https://github.com/linebender/tiny-skia/blob/e48b9027762d33731e60e40eb17eaa4f583b0185/src/pixmap.rs#L25-L53), [resvg color-space contract](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/lib.rs#L28-L38), [CLI background behavior](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/main.rs#L727-L743)

The output-affecting `usvg::Options::default()` values are: no resource base, `96` DPI, default font family `Times New Roman`, default font size `12`, languages `["en"]`, shape rendering `GeometricPrecision`, text rendering `OptimizeLegibility`, image rendering `OptimizeQuality`, fallback viewport `100 x 100`, an empty font database, default font and image resolvers, and no injected stylesheet. They should be recorded explicitly rather than inherited implicitly. [Source: Options fields and defaults](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/options.rs#L11-L123)

The rendering hints are material: `GeometricPrecision` enables shape antialiasing; text `OptimizeLegibility` maps to antialiased `GeometricPrecision`; image `OptimizeQuality` maps to bicubic filtering. [Source: rendering-hint defaults and shape AA](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/tree/mod.rs#L94-L183), [text hint mapping](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/flatten.rs#L16-L21), [image filter mapping](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/image.rs#L173-L203)

## Font database and matching behavior

- `Options::default()` creates an empty `fontdb::Database`; merely compiling system-font support does not populate it. The stock CLI explicitly calls `load_system_fonts()` when text is present unless `--skip-system-fonts` was given. [Source: empty default database](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/options.rs#L103-L121), [CLI text check](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/main.rs#L83-L96), [CLI font loading](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/resvg/src/main.rs#L599-L618)
- Deterministic loading is available from an empty database through `load_font_data(Vec<u8>)` or `load_font_source(Source::Binary(...))` in a fixed manifest order. Each sfnt collection face is added; there is no duplicate replacement in this path. Avoid `load_fonts_dir`: it recursively consumes unsorted `read_dir` results and only considers TTF/OTF/TTC/OTC extensions. [Source: binary loading](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L167-L229), [directory loading](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L295-L387)
- Family-name matching is exact string equality. Face names come from typographic family name ID 16, falling back to family name ID 1; full names such as `Arial Bold` are not family keys. Matching considers requested families in order, then stretch, style preference, and weight. If multiple candidates survive all axes, the implementation returns the first candidate in database iteration. Exact `(family, stretch, style, weight)` collisions therefore expose database order and should either be rejected by the profile or have their complete ordered face list approved. [Source: family metadata](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L824-L852), [name extraction](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L1034-L1094), [query](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L646-L679), [style/weight selection and tie](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L1207-L1342)
- fontdb's generic defaults are `Times New Roman`, `Arial`, `Comic Sans MS`, `Impact`, and `Courier New`, except that `fantasy` defaults to `Papyrus` on macOS. All five generic mappings must be set explicitly to loaded profile families. The separate `Options::font_family` default must also be explicit. [Source: database defaults](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L167-L190), [generic-family setters](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L621-L658)
- usvg's default primary selector tries the SVG family list in order and then always appends generic `serif`. Its glyph fallback selector scans every face in database order. Despite the comment saying the fallback should have the same style, the code rejects a face only when style, weight, and stretch all differ, then chooses the first remaining face that contains the character. Fallback order is therefore part of output identity. [Source: primary selector](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/mod.rs#L79-L140), [fallback selector](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/mod.rs#L143-L189)

## Embedded `@font-face`, WOFF2, and shaping

CSS `@font-face` with a data-URL WOFF2 is **not supported** by this stack:

- usvg feeds embedded `<style>` text to simplecss. simplecss explicitly skips every at-rule, including `@font-face`; therefore the data URL is never offered to a font loader. [Source: usvg stylesheet path](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/svgtree/parse.rs#L624-L652), [simplecss limitation](https://github.com/linebender/simplecss/blob/6eacb39ca5c4c2390bfde374ed0651f0e35c9d8d/src/lib.rs#L11-L21), [at-rule skipping code](https://github.com/linebender/simplecss/blob/6eacb39ca5c4c2390bfde374ed0651f0e35c9d8d/src/lib.rs#L287-L309)
- resvg's own SVG 2 status leaves WOFF support unchecked, and its SVG 1.1 unsupported list includes the SVG font-face elements. [Source: SVG 2 status](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/docs/svg2-changelog.md#L105-L115), [unsupported SVG font elements](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/docs/unsupported.md#L5-L21)
- Manually passing WOFF2 bytes to fontdb does not repair this. fontdb calls `ttf_parser::RawFace::parse`; that parser accepts only TrueType, OpenType sfnt, and TTC magics, not WOFF/WOFF2 container magics. ttf-parser exposes a lower-level raw-table API useful to a separate WOFF decoder, but fontdb does not perform that decoding. [Source: fontdb parse call](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L1034-L1055), [accepted ttf-parser magics](https://github.com/harfbuzz/ttf-parser/blob/56c33b910b03ca152f78363ec471c5dfd97c3069/src/lib.rs#L124-L145), [normal parser and raw-table note](https://github.com/harfbuzz/ttf-parser/blob/56c33b910b03ca152f78363ec471c5dfd97c3069/src/lib.rs#L817-L918)

Consequently, the Rust gate must preload reviewed sfnt bytes under the exact family/style metadata used by the SVG. The embedded WOFF2 remains inert. The official and candidate SVG must be rendered with the same preloaded database, ordered face manifest, generic-family mappings, and resolver policy; otherwise the gate is comparing host fallback rather than SVG appearance.

With the `text` feature, usvg performs text layout and converts glyphs to renderable paths/images during parsing. It uses rustybuzz `0.20.1`, ttf-parser outlines, and `unicode-bidi`: the paragraph base level is forced LTR, visual runs set LTR/RTL direction, rustybuzz guesses script, and no shaping language is set. Kerning is on unless disabled by SVG properties; `small-caps` enables `smcp`. `0.47.0` additionally applies variable-font settings and automatic `opsz` when present. [Source: usvg text conversion](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/mod.rs#L198-L215), [bidi and shaping](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/layout.rs#L1395-L1515), [rustybuzz property guessing](https://github.com/harfbuzz/rustybuzz/blob/8c52723ff75e91a33ae36e527baed871097e64bf/src/hb/buffer.rs#L629-L653), [kerning and optical sizing](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/text.rs#L258-L303), [0.47.0 variable-font change](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/CHANGELOG.md#L13-L23)

Fallback reshapes the whole text with each selected fallback font. If one fallback resolves every glyph, it replaces the entire run; otherwise usvg only merges replacements when glyph counts agree, with an upstream TODO noting that glyph-index rather than cluster replacement is not fully accurate. This is another reason for a separate typography allowance and fixed fallback corpus in the Rust portability gate. [Source: fallback shaping](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/text/layout.rs#L1292-L1392)

## Platform-dependent paths to disable

- Do not call `load_system_fonts`, and do not enable the `system-fonts` feature. fontdb scans Windows directories derived from `SYSTEMROOT` and `USERPROFILE`; macOS system, asset, network, and `HOME` directories; and Unix fontconfig files/aliases/directories derived from `FONTCONFIG_FILE`, `XDG_CONFIG_HOME`, `HOME`, and `/etc/fonts`, with fixed-directory fallbacks. Both available faces and generic aliases can vary. [Source: system discovery](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L389-L579)
- Do not use `load_fonts_dir`; filesystem enumeration is not sorted. Do not enable `memmap-fonts` or load file-backed faces: the fontdb API warns that mapped file changes can become visible to the process. Use owned binary font bytes. [Source: directory enumeration](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L354-L387), [mapped-source safety](https://github.com/RazrFalcon/fontdb/blob/62cfd96671eba4debe73eeecf541b1a3a051d223/src/lib.rs#L729-L775)
- Replace the default image string resolver with a resolver that rejects non-data references. The default treats arbitrary strings as local paths, resolves relative paths through `resources_dir` or the process working directory, and reads existing files. usvg performs no network requests, but local filesystem access is allowed by default. Retain a deliberately selected data-URL resolver for manifested embedded PNG/JPEG/GIF/WebP/SVG only. [Source: image resolver contract and local-file default](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/image.rs#L15-L114), [data URL dispatch](https://github.com/linebender/resvg/blob/3a0fdba53ccf2d346b54cc53ba7adf0ee60d0707/crates/usvg/src/parser/image.rs#L288-L301)
- Set every output-affecting option and all generic font families explicitly, even when matching upstream defaults. In particular, fixed `languages` avoids `systemLanguage` drift, fixed DPI controls physical units, and explicit rendering hints prevent future default drift.

## Decision-relevant profile

A reproducible hard Rust-viewer gate is feasible, but it is not "run resvg on the SVG with defaults." Its approved profile needs one exact resvg/usvg source identity and lockfile; a custom library tool with `text` and the required raster decoders but no system-font/memmap features; native rounded dimensions and identity render transform; transparent sRGB output; all `Options` values frozen; local-file image resolution disabled; and a fresh font database populated from an ordered, hashed set of predecoded sfnt bytes with explicit generic mappings and collision policy.

The largest compatibility qualification is typography: resvg cannot consume Excalidraw's embedded CSS data-URL WOFF2, and its pure-Rust shaping/fallback pipeline is not Chromium's. Preloading the same reviewed sfnt database makes the Rust gate deterministic and useful as a portability guard, but does not turn it into the Chromium compatibility authority.
